    About GitHub Pulse

    GitHub Pulse is a backend you build and deploy. It loads public GitHub activity into Postgres, serves it through a FastAPI API, and adds an AI assistant that answers questions in plain English, with links to the sources. It shows an employer that you can build a Python backend with AI, caching, background jobs, tests and a live deployment.

    DataGH Archive, a free public record of GitHub events. Nothing from EY and nothing confidential.
    Why this projectIt covers what AI backend roles ask for in one place: FastAPI, Postgres, Redis, workers, LLM APIs, RAG, evaluation, Docker, CI and AWS.
    Interview line"I built and deployed a Python backend with an AI assistant on public GitHub data: streaming answers, a Redis cache, background workers, measured answer quality and tests in CI."
    Why this track

    An AI backend engineer builds the server side of AI products: calls models reliably, gives them the right data, returns validated JSON, streams answers, caches, runs background jobs, and measures quality and cost. It is backend work with an AI layer, so your Node, TypeScript, Postgres and data pipeline experience carry over directly.

    Your edgeAn XBRL data pipeline at EY (265K+ filings, validation and data-quality work) and WhisprLive (real-time sockets, auth, rate limiting, caching).
    Gaps to closeDocker, AWS, CI, Redis, job queues, FastAPI, LLM APIs and evaluation. This tab covers all of them.
    Python or TypeScriptBuild the main app in Python, since most AI tooling is Python first. Use TypeScript for the chat page and, if you like, the queue (BullMQ). Having both is an advantage.
    Job titlesSearch AI Engineer, Applied AI Engineer, LLM Engineer, Backend Engineer (AI) and Software Engineer (Python). Titles vary a lot between companies.
    Keep EY outUse only public data and fresh code. Do not reuse company code or client data.

    Words you will meet
    EndpointOne URL of your API that does one job, for example GET /repos/trending.
    Pydantic modelA class that describes the shape of data and rejects data that does not match.
    DependencyIn FastAPI, a function that provides something an endpoint needs, such as a database connection.
    IdempotentRunning a step twice gives the same result as running it once. It makes retries safe.
    EmbeddingA list of numbers that represents the meaning of a piece of text. Similar texts get similar numbers.
    RAGFind the most relevant text first, then give it to the model so its answer is based on real sources.
    ChunkingSplitting long text into small pieces so each piece can be embedded and retrieved on its own.
    Structured outputThe model returns JSON that matches a schema you defined, so your code can rely on it.
    Tool useThe model asks to run one of your functions. You run it and send the result back. Also called function calling.
    Hit rate at kHow often the right source appears in the top k search results.
    SSEServer-Sent Events. The server keeps one HTTP response open and sends pieces as they are ready.
    Cache hit rateThe share of requests answered from Redis without calling the model.
    WorkerA separate process that takes jobs from a queue so the API can reply straight away.
    TraceA record of one request: what was retrieved, which tools ran, tokens used, time taken and cost.
    Prompt injectionText in the data that tries to give the model new instructions. Treat retrieved text as data, never as orders.
    EvalA fixed set of questions with known answers that you re-run to measure quality.

    How you actually get the job

    Track A: product-based company (main goal)

    1. Pass the online test first. Most product-company screens are DSA plus SQL, so your DSA and SQL practice matters more than any certificate.
    2. Make a target list of 30 companies before you start applying: 10 reach, 10 realistic, 10 safe. Include Indian product companies, GCCs of global firms and fintech data teams. Note each careers URL.
    3. Get the project live before you apply. The live AI assistant on your own backend is your proof that you can build and run it.
    4. Once the project is live, message 5 engineers or recruiters a week on LinkedIn. Send a 3-line note and your repo link, and ask for a referral only after they reply. Referrals beat cold applications at product companies.
    5. Expect a loop of online test, DSA round, SQL round, a backend or AI system design round (for example, design a question-answering service over documents), then hiring manager. Practice each one in your mocks.
    6. Negotiate with a competing offer or your current pay in hand. Ask for the CTC split in writing before you accept.

    Track B: remote USD role (next goal, be realistic)

    1. Know the odds. Many US remote roles want US work authorization, several years of experience, or heavy time-zone overlap. With about 1.2 years, a direct remote USD offer is possible but uncommon.
    2. Use the likely route. Move to a strong product company or GCC first, build 2 to 3 years there, then apply remote. This plan makes that first move possible and still lets you try Track B in parallel.
    3. Target remote-first companies that say they hire in India or anywhere. Search Wellfound, Himalayas, We Work Remotely, RemoteOK and LinkedIn with the remote filter, and read each posting for location limits before applying. Many hire through an employer-of-record service such as Deel or Remote.
    4. Build public proof. Keep the repo, README, architecture diagram and demo video polished, and write one short post on what you learned. Remote teams hire on written proof.
    5. Practise async communication. Write clear updates, answer in complete sentences and be ready to work a few hours of US overlap. Include a line on this in your applications.
    6. Protect yourself. Never pay a fee to get a job or to receive equipment, and be wary of offers that skip interviews. Check your EY contract on outside work, and ask a chartered accountant about tax on foreign income before you accept USD pay.
    What the interview loop looks like

    Expect an online test, a DSA round, a SQL round, a backend or AI system design round, then the hiring manager. Practise each one in your mocks.

    The DSA and SQL tabs cover the first rounds. The system design tasks and the mocks on this tab cover the design round.

    When to do these

    Do the data pipeline stages only if a job you want asks for Airflow, Spark or dbt, or if you finish the main plan early. Go in order: data modeling, AWS and S3, Airflow, Spark, dbt. Blog posts and open source help you stand out but are not needed for the main goal.

    Why AWS for you

    It is where product and startup hiring sits. AWS holds about 32% of the global cloud market and is described as the common choice of startups and tech-forward companies. Those are the employers behind product-based and remote roles.

    Azure leans enterprise. It is strongest in Microsoft-heavy enterprises and regulated industries such as banking and insurance. That is a good market, but it is closer to the service-company path you want to leave.

    The core skills move with you. SQL, Python, Spark, Airflow, dbt and pipeline design work on any cloud, so picking AWS now costs little if you later land on Azure or GCP.

    Source: Data Engineer Academy, AWS vs Azure data engineering.

    Blog on your portfolio

    Write three posts while you build. Each one should come from something you actually did, so it is easy to write and hard to fake.

    Post ideas and when to write them

    Post ideaHow I made my Airflow pipeline safe to rerun. Cover idempotency, retries and backfills.
    Post ideaPartitioning and Parquet: how I reduced the data Athena scans. Show before and after sizes.
    Post ideaWhat I learned building a GitHub events pipeline on AWS. This is post 1.
    Post ideaChunk size and retrieval: what changed my search results.
    Post ideaHow I measured my RAG app and what the numbers showed. This is post 2.
    Post ideaWhat it costs to run a small data pipeline on AWS, with an itemised breakdown.
    Post ideaHow I prepared for the AWS Data Engineer exam: my plan, resources and what I skipped.
    Post ideaLessons from parsing messy regulatory filings into clean tables. Keep it general: no client names, no confidential details.
    Post ideaMy first open-source pull request. This is post 3.

    Post template

    1. Problem. What were you trying to do, in two or three sentences?
    2. Approach. What did you build or try? Add one diagram and one short code snippet.
    3. What broke. The bug, the slow query or the wrong answer, and how you found the cause.
    4. Numbers. Before and after results, such as runtime, cost or accuracy.
    5. What I would do differently. Two or three honest lines.
    6. Links. The repo, the relevant folder and the demo.

    Aim for 800 to 1,200 words. Do not include anything from EY or any client.

    How to add a blog to your portfolio

    1. Keep each post as a Markdown file in your portfolio repo, for example src/posts/airflow-reruns.md, with a title, date, short summary and tags at the top.
    2. Add a Blog page that lists the posts (title, date, summary), and a post page at /blog/post-name.
    3. Render the Markdown with react-markdown, or with MDX if you want React components inside posts. Add code highlighting.
    4. Set a page title, a description and Open Graph tags for each post, so the link shows a proper preview when you share it on LinkedIn.
    5. Deploy the way you deploy your portfolio now, then open each post on your phone to check it.
    6. Share each post on LinkedIn with a two-line summary and the link. Put your blog link at the top of your resume and in your GitHub profile.

    Tools: react-markdown and MDX for rendering markdown in a React portfolio.
